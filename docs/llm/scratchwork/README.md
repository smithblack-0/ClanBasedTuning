# LLM scratchwork

Status: preliminary, non-authoritative, and disposable

This directory may preserve tentative implementation ideas, option fragments, and questions that are useful to future work but have not been accepted as project design or planning authority.

Scratchwork must obey the governing roadmap, accepted decisions, and milestone gates. It may not change their meaning, assign work, narrow an acceptance gate, or predesign a later milestone. A note such as “a `PopulationBasedTraining` subclass may be worth investigating for the transition” belongs here; a requirement that the later milestone use that subclass does not.

When active work establishes a real dependency for a later milestone, add the dependency directly to that milestone’s gate at the behavioral level. State what current capability must be connected or preserved and what observable result must occur. Do not decide the future class, hook, adapter, framework seam, or strategy while recording the dependency.

Scratchwork becomes authoritative only when its relevant content is deliberately moved into the proper accepted design, scoped plan, decision, or gate through the normal review process. Deleting this directory must not remove project truth.

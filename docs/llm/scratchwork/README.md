# LLM scratchwork

Status: preliminary, non-authoritative, and disposable

This directory preserves useful but unaccepted context: framework research, source
observations, rejected options, tentative implementation ideas, exploratory API
shapes, and questions for later work. It is not limited to future plans.

Scratchwork must obey the governing roadmap, accepted decisions, and milestone gates.
It may not change their meaning, assign work, narrow an acceptance gate, or predesign
a later milestone. A note that a `PopulationBasedTraining` subclass may be worth
investigating belongs here; a requirement that a later milestone use it does not.

When active work establishes a real dependency for a later milestone, add the
dependency directly to that milestone's gate at the behavioral level. State what
current capability must be connected or preserved and what observable result must
occur. Do not decide the future class, hook, adapter, framework seam, or strategy while
recording the dependency.

Scratchwork becomes authoritative only when its relevant content is deliberately moved
into the proper accepted design, scoped plan, decision, or gate through the normal
review process. Deleting this directory must not remove project truth.
